# 設計の記録 — なぜこの測位アルゴリズムにしたか

> **この文書**: **なぜ**この設計にしたかの記録 (実装前の検討と、採らなかった案)。**現在の使い方の情報源としては使わないこと** — 実装は動き続けるので、今どう動くかは [UWB_ALGORITHMS.md](UWB_ALGORITHMS.md)、使い方は [TUTORIAL.md](TUTORIAL.md)。 → [ドキュメント一覧](README.md)

特定の UWB チップ (DW1000/DW3000, NXP SR150, Qorvo, ESP32-UWB …) に依存せず、
**各 UWB 用に書いた HAL から観測量を受け取って位置を出す**ライブラリの設計。
なぜその手法を選んだかを残すための文書。式の導出は [UWB_ALGORITHMS.md](UWB_ALGORITHMS.md)、
使い方は [TUTORIAL.md](TUTORIAL.md)、HAL との取り決めは
[UWB_PROTOCOL.md](UWB_PROTOCOL.md)、式の導出は [UWB_ALGORITHMS.md](UWB_ALGORITHMS.md)。

## 決定事項

| 項目 | 決定 |
|---|---|
| 第一級の観測方式 | **DS-TWR (距離)**。TDoA と AoA も残差の形が同じなので同じソルバで扱える |
| 次元 | **3D・立体配置**。`SolveConfig(dim=...)` で 2D / 2.5D にも切り替えられる |
| 実装 | **Python + 後で C 移植前提**。scipy を使わず GN も EKF も自前 |
| UI | **ブラウザ UI (ローカル起動)**。外部 CDN 不使用 |

以下は選定の理由。実装は `uwb_loc/` にある。

---

## 0. 全体像

HAL とアルゴリズムの間を「観測量 (measurement)」で切る。HAL はチップ固有の
レジスタ操作・タイムスタンプ処理・測距シーケンスを担当し、ライブラリ側には
**物理量になった観測値と、その品質情報だけ**を渡す。

```
 ┌─────────┐   Measurement    ┌──────────────────────────────────────┐
 │  HAL    │ ───────────────→ │  前処理    スナップショット    追跡    │ → 位置
 │ (chip)  │  range / TDoA /  │  バイアス   閉形式 + WNLS     EKF/UKF │   共分散
 └─────────┘  AoA / CIR 品質  │  外れ値除去  (Lv0-Lv2)        (Lv3)   │   品質指標
      ↑                       └──────────────────────────────────────┘
 実機 or シミュレータ (同じインターフェイスなので差し替え可能)
```

この境界の置き方には理由がある。

- チップごとに違うのは「時刻をどう測るか」までで、**距離になってしまえば同じ**。
- 逆に、チップ固有の品質情報 (CIR の first-path 電力、受信電力、
  first-path index) は NLOS 判定に効くので、**共通の品質フィールドに正規化して
  必ず上げてもらう**。ここを捨てると屋内でロバスト性が出ない。
- シミュレータも実機 HAL も同じ型を出すので、アルゴリズムのコードは 1 本で済む。

## 1. UWB が出せる観測量と、対応するアルゴリズム

| 観測方式 | 得られる量 | 同期要件 | 収容タグ数 | 主な用途 |
|---|---|---|---|---|
| SS-TWR | 距離 (クロックドリフト誤差大) | 不要 | 少 | 簡易 |
| DS-TWR / AltDS-TWR | 距離 (ドリフト 1 次項が消える) | 不要 | 少〜中 | **既定** |
| TDoA (uplink) | 距離差 | アンカー間同期が必須 | 非常に多 | 多数タグ |
| TDoA (downlink) | 距離差 | アンカー間同期が必須 | 無制限 (タグは受信のみ) | 多数タグ・低消費 |
| PDoA / AoA | 方位角 (・仰角) | 不要 | 少 | アンカー 1 台測位 |
| RSSI / CIR | 品質・NLOS 特徴量 | — | — | 重み付け、NLOS 判定 |

ライブラリとしては **距離 (range)・距離差 (TDoA)・角度 (AoA) の 3 種を観測量の
基本型**として扱い、どれが来ても同じソルバに流せるようにする。混在
（アンカー A からは距離、アンカー B からは角度）も残差ベクトルを連結するだけで
自然に扱える。

## 2. スナップショット測位（1 エポック分の観測から位置を出す）

### 2.1 距離ベース (ToA / TWR)

観測モデル: `r_i = ||p − a_i|| + b + n_i`, `n_i ~ N(0, σ_i²)`
（`a_i` はアンカー座標、`b` は共通距離バイアス。TWR なら `b = 0` に固定、
残留アンテナ遅延を吸収させたいときだけ未知数にする）

**(a) 線形化最小二乗 (LLS) — Lv0**
基準アンカーとの差をとると 2 次項 `||p||²` が消えて線形方程式になり、
擬似逆行列 1 発で解ける。反復なし・初期値不要で最速。ただし基準アンカーの
選び方で精度が変わり、統計的には最適でない。**デバッグと初期値供給用**。

**(b) Beck の厳密解 (GTRS) — Lv2 の初期解**
`||p||²` を補助変数 `g` として制約付き 2 次計画に書き直すと、
Generalized Trust Region Subproblem になり、**1 変数 λ の単調な永年方程式を
二分法で解くだけで大域最適解が求まる**。反復発散がなく、LLS より偏りが小さい。
初期値問題を根本的に回避できるので、これを既定の初期解にしたい。

**(c) 重み付き非線形最小二乗 (WNLS, Gauss–Newton / Levenberg–Marquardt) — Lv1**
`J(p) = Σ w_i (r_i − ||p − a_i||)²`, `w_i = 1/σ_i²` を最小化。
最尤推定なので誤差がガウスなら最良。初期値は (a) か (b)、
追跡中なら**前エポックの推定値**を使う。LM にしておけば幾何が悪いときも落ちない。
`scipy.optimize.least_squares` に頼らず自前の GN を持つほうが、
後で C に移植するときに楽（重み・ロバスト損失も自前で入れられる）。

**(d) 幾何劣化と可観測性**
- アンカーが**同一平面上**（天井 4 隅など）に並ぶと z 方向がほぼ不可観測。
  → 高さ既知拘束 (`z = const`) か、気圧計・ToF・IMU との融合が必須。
  ライブラリ側は「解く次元を 2D / 2.5D / 3D で選べる」ようにする。
- 解が 2 つに割れる配置（アンカー全部が一直線、3 本で 3D）では鏡像解が出る。
  **z > アンカー平面** のような事前情報で片方を落とす API を用意する。

### 2.2 TDoA ベース

観測モデル: `d_ij = ||p − a_i|| − ||p − a_j|| + n`

- **Chan の 2 段階 WLS**: 閉形式。1 段目で `||p − a_1||` を補助未知数として WLS、
  2 段目でその拘束を使って補正。近距離・遠距離とも実用精度で、初期値不要。
  → **TDoA の既定の初期解**。
- **Fang**: 閉形式だが観測数がちょうど最小のときのみ。冗長観測を活かせない。
- **Bancroft**: GPS 由来の閉形式。距離 + 共通バイアス型 (2.1 の `b` 未知) にそのまま使える。
- いずれも **GN/LM で refine** して仕上げる（`b` を未知数に含めた WNLS と同じ形になる）。

### 2.3 角度 (AoA/PDoA) 併用

アンカー 1 台でも「距離 + 方位角」で 2D 位置が出る。残差ベクトルに
`atan2` 系の残差を追加し、角度の巻き付き (±π) を正しく畳む処理だけ入れる。
重みは `1/σ_θ²`（角度分散は距離が遠いほど位置誤差に効くので、
自動的に「遠いアンカーの角度は効きにくい」正しい振る舞いになる）。

## 3. ロバスト化 (NLOS 対策) — 屋内では**ここが精度を決める**

見通し外 (NLOS) では電波が回り込む分、距離は**必ず正側に**偏る (数十 cm〜数 m)。
ガウス仮定の最小二乗はこれに極端に弱いので、以下を段階的に入れる。

1. **物理的ゲート**: 負の距離、最大到達距離超え、アンカー間距離との三角不等式
   違反を落とす。ほぼコストゼロで効く。
2. **χ² 残差ゲーティング**: 予測位置からの残差 `(r_i − r̂_i)²/σ_i²` が閾値超えなら
   そのエポックで不採用。追跡フィルタと組むと非常に強い（イノベーションゲート）。
3. **M 推定 (Huber / Tukey) + IRLS**: 外れ値を捨てずに重みを下げる。
   観測数が少ないときに「捨てすぎて解けない」のを防げる。**既定はこれ**。
4. **片側損失**: NLOS バイアスが正側だけという物理を使い、
   `r_meas − r̂ > 0` 側だけ損失を緩める非対称損失。UWB では素直に効く。
5. **RANSAC**: アンカーが 6 本以上あるときのみ。最小構成 (3〜4 本) で仮解を作り、
   インライア最大の組を採る。NLOS が過半を占めるような悪条件で最後の砦になる。
6. **CIR 特徴による LOS/NLOS 分類**: HAL が上げてくる
   `first_path_power − peak_power`、立ち上がり時間、受信電力から
   NLOS 確率を推定し、`σ_i` を膨らませる。チップ非依存に扱えるよう、
   HAL には**正規化した品質スコア (0–1) と生の特徴量の両方**を出させる。

## 4. 追跡フィルタ (時系列)

### 4.1 密結合 EKF を既定にする

スナップショット位置をフィルタに入れる（疎結合）のではなく、
**距離そのものを観測として EKF に直接入れる（密結合）**ことを推奨する。理由:

- アンカーが 3 本未満しか見えないエポックでも**更新できる**
  （疎結合だとそのエポックは丸ごと捨てになる）。
- TWR はアンカーを順番にポーリングするので、観測は**もともと非同期**に届く。
  「1 スキャン = 1 エポック」に束ねる必要がなく、届いた瞬間に predict→update
  すればよい。レイテンシが下がり、動きの速い機体で有利。
- 幾何が悪い方向の情報だけを部分的に取り込める（共分散が正しく効く）。

状態: `x = [p, v]` (等速 CV) を既定、機動が激しいなら `[p, v, a]` (CA) か
Singer モデル。プロセスノイズは「加速度の白色化」で 1 パラメータ (`σ_a`) にまとめ、
UI から触れるようにする。

### 4.2 使い分け

| 手法 | 使いどころ |
|---|---|
| EKF (CV/CA) | **既定**。計算が軽く組込みに載る |
| UKF | 至近距離でアンカーを跨ぐなど距離の非線形性が強い場合 |
| IMM (CV+CA) | 停止と高速移動が混在するとき |
| パーティクルフィルタ | NLOS が支配的、または地図/壁拘束を入れたいとき |
| ESKF (誤差状態 KF) | **IMU と融合する場合**。姿勢まで推定。ドローン向けはこれ |

### 4.3 時刻の扱い

- 観測には **HAL 側で打ったタイムスタンプ**を必ず付ける（受信時刻ではなく
  測距が成立した時刻）。予測ステップはこの時刻差 `Δt` で回す。
- 遅れて届いた観測 (out-of-sequence measurement) は、
  ①捨てる ②状態を巻き戻して再適用 ③retrodiction のいずれか。既定は①、
  オプションで②を用意する。

## 5. キャリブレーションと設営支援

実運用で精度が出ない原因の大半はアルゴリズムでなく**設営とキャリブレーション**なので、
ライブラリに含める。

- **アンテナ遅延推定**: 既知距離での最小二乗、または 3 台巡回法
  (3 台の相互 TWR から各機の遅延を分離)。デバイスごとに保存。
- **距離バイアスモデル**: `r_true ≈ α r_meas + β` (+ 受信電力依存の補正項)。
  実測から当てはめる関数を提供。
- **アンカー座標の自己推定 (self-survey)**: アンカー間で相互 TWR
  → 古典的 MDS で初期配置 → 非線形最適化で仕上げ。
  座標系の不定性 (回転・並進・鏡像) は「アンカー 0 を原点、1 を x 軸上、
  2 を xy 平面の正側」で固定。**巻き尺で測る作業が消えるので効果が大きい。**
- **配置評価**: GDOP マップと CRLB (Cramér–Rao 下限) をグリッド上に描く。
  「その部屋のどこで誤差何 cm になるか」を設置前に見られる。

## 6. 出力する品質指標

位置だけ返すライブラリは実運用で困るので、毎エポック以下を返す。

- 推定位置 `p̂` と **共分散 `P`** (3×3)
- 残差 RMS、使用アンカー数 / 全アンカー数、除外されたアンカー ID
- GDOP (幾何精度劣化係数)
- NLOS と判定されたリンクとその確率
- 収束フラグ・反復回数

シミュレータでは真値と突き合わせて **CEP50 / CEP95、誤差 CDF、
軸別 RMSE、外れ率**を出す。UI のメイン指標もこれにする。

## 7. 忠実度レベル (段階的実装)

**同一インターフェイスで差し替えられる測位器**として忠実度の段階を切る。
用途によって必要な精度と計算量が違うので、上から順に試して
「どこまで凝れば足りるか」を測れるようにしておく。

| Lv | 中身 | 想定 |
|---|---|---|
| **Lv0** | LLS 三辺測量（閉形式、反復なし） | 動作確認・初期値・最軽量 |
| **Lv1** | WNLS (GN/LM) + χ² ゲート | 基本の静的測位 |
| **Lv2** | Beck 閉形式初期解 + Huber IRLS (+RANSAC) | **NLOS のある屋内の既定** |
| **Lv3** | 密結合 EKF/UKF (CV/CA)、IMU 融合は ESKF | 移動体・ドローン |

```python
class PositionEstimator(ABC):
    def update(self, batch: MeasurementBatch) -> Fix: ...
    def reset(self) -> None: ...
```

`Fix` に位置・共分散・品質指標を載せる。Lv0–Lv2 はステートレス、
Lv3 だけ内部状態を持つが、`update()` の呼び方は同じにする。

### 推奨する既定パイプライン

```
HAL → 単位/バイアス補正 → 物理ゲート → Beck 閉形式(初期解)
    → Huber-IRLS WNLS → 密結合 EKF (CV) → Fix (位置 + 共分散 + 品質)
```

静止ノードなら EKF を外して Lv2 止まり、ドローンなら Lv3 + IMU、
という切り替えを設定 1 つでできるようにする。

## 8. シミュレータの誤差モデル（UI 側で使う）

アルゴリズム評価に必要な誤差要因は次の通り。UI からこれらを振って、
測位アルゴリズムの Lv を比較できるようにする。

- 測距ノイズ `σ` (距離依存: `σ(d) = σ0 + k·d`)
- NLOS: リンクごとの発生確率 + 正側バイアス (指数分布 or 対数正規)
- 欠測 (パケットロス率)、更新レート、アンカーごとのレイテンシ
- アンテナ遅延の残差、アンカー座標の設置誤差
- タグの運動 (静止 / ランダムウォーク / 一定速 / 8 の字軌道 / 記録軌跡)
- クロックドリフト (TDoA 評価用)、アンカー間同期誤差

## 9. 実装で変えた点

提案どおりに作ってみて、実測 (シミュレータ上の比較) で分かった調整が 2 つある。

**RANSAC は常時走らせない。** 提案では Lv2 の一部として常時実行するつもりだったが、
そうすると Lv1 より悪化した (RMSE 0.30 → 0.40 m)。3 次元の最小構成は 4 本で、
そこから作る仮解自体が数十 cm の誤差を持つため、その仮解を基準にインライア判定すると
**まともな観測まで落としてしまう**。通常の解き方の規格化残差が 3σ を超えたときだけ
起動し、しかも結果が改善したときだけ採用する形に変えた。判定しきい値も σ の
4 倍と広めに取っている (仮解自身の誤差を見込むため)。

**Lv2 は前回値から温め直さない。** ロバスト重みは残差から作るので、前回の推定に
引きずられると外れ値に固着しうる。毎エポック Beck の閉形式から解き直す。
閉形式が大域最適解を出すので、初期値を捨てても収束性は落ちない。

参考: 同一の観測列 (8 台立体配置、σ0=8 cm、NLOS 15%、10 Hz) での比較。

| Lv | RMSE 3D | CEP95 | 最大 |
|---|---|---|---|
| Lv0 | 0.607 | 0.570 | 3.13 |
| Lv1 | 0.376 | 0.255 | 1.83 |
| Lv2 | 0.311 | 0.194 | 1.82 |
| Lv3 | 0.172 | 0.137 | 0.64 |

NLOS を 35% に上げても順序は変わらない (Lv0 1.05 → Lv3 0.33 m)。

## 10. まだ入れていないもの

必要になった時点で足す。現状の構造のまま追加できる。

- **IMU 融合 (ESKF)** — 姿勢まで推定する誤差状態カルマン。ドローンで
  高いレートが要るときに効く。Lv3 の状態を拡張する形になる
- **Chan 法の 2 段目** — TDoA の閉形式に `d_ref = ||p - a_ref||` の拘束を使う補正。
  1 段目 + Gauss-Newton で実用精度が出ているので後回しにした
- **IMM (CV+CA の混合)** — 停止と高速移動が混在する用途
- **パーティクルフィルタ** — 地図・壁の拘束を入れたい場合
- **CIR からの NLOS 分類器** — 現状は HAL が上げる `quality` を σ に反映するだけ。
  実機のログが溜まれば学習に置き換えられる (`raw` に生値を残してある)
